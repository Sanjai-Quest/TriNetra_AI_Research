2.2 Canonical Normalization Rules (SKU, Weight, Size, Color, Timestamps)
You must write highly robust Python parsers under phase-1/normalization/ that preserve the original raw input string while deriving and storing the canonical value [97]:

SKU Normalization:
Logic: Convert string to uppercase, strip all spaces, and insert a single hyphen separating letters and numbers [16].
Examples: "TS-204", "TS204", "ts-204", "TS 204" $\rightarrow$ "TS-204" [16].
Weight Normalization:
Logic: Convert and parse all standard unit expressions (grams, kg, kilograms) into a standard, raw integer in grams [16].
Examples: "500g", "0.5kg", "500 grams", "0.5 kilograms" $\rightarrow$ 500 [16].
Size Normalization:
Logic: Map size variations, standard abbreviations, and descriptive words into standard canonical shorthand [16].
Examples: "XL", "x-large", "extra large", "extra-large", "xl" $\rightarrow$ "XL" [16].
Color Normalization:
Logic: Convert string to uppercase and strip all modifiers (such as "bright", "dark", "light"), preserving only the primary base color [17].
Examples: "red", "RED", "dark red", "bright red" $\rightarrow$ "RED" [17].
Timestamp Normalization:
Logic: Parse a wide array of date formats and enforce timezone-aware strict ISO 8601 UTC representation [17].
Examples: "2026-08-23T10:00:00Z", "08/23/2026 10:00 AM", "23-Aug-2026 10:00:00" $\rightarrow$ "2026-08-23T10:00:00Z" [17].

3.2 Layer 1: Deterministic Consistency Rules
You must build deterministic validation logic to identify logical, attribute, and chronological inconsistencies [101]:

SKU / Identity Inconsistencies: Raise an IDENTITY_CONFLICT of severity HIGH if SELLER.sku != ORDER.sku or WAREHOUSE.sku != ORDER.sku [21].
Variant Inconsistencies: Raise a VARIANT_CONFLICT of severity HIGH if variant attributes (such as size or color) do not match across available sources (e.g., WAREHOUSE.size != ORDER.size) [21, 39, 101].
Chronological Inconsistencies: Sort evidence chronologically. Raise a TEMPORAL_CONFLICT of severity MEDIUM if $T_{event_a} > T_{event_b}$ where event $a$ should logically precede $b$ based on the canonical flow: ORDER $\rightarrow$ SELLER $\rightarrow$ WAREHOUSE $\rightarrow$ CARRIER $\rightarrow$ RETURN [22].
Completeness Gaps: Evaluate if mandatory sources [ORDER, SELLER, WAREHOUSE, CARRIER, RETURN] are present [22]. If missing, raise MISSING_EVIDENCE of severity LOW-MEDIUM and output the list of missing sources [23].
3.3 Layer 2: Statistical Anomaly Detection (Outbound/Inbound Weights)
You must write mathematical anomaly detection that dynamically identifies physical discrepancies [102]:

Logic: Compute the historical average weight (mean_weight) and sample standard deviation (stddev_weight) for the specific canonical product ID [21].
Statistical Outlier Check: Flag a record as a WEIGHT_ANOMALY of severity MEDIUM-HIGH if any scan's weight falls outside the historical mean standard deviation boundary [21]: $$\text{weight} < (\text{mean} - 3 \times \text{stddev}) \quad \text{OR} \quad \text{weight} > (\text{mean} + 3 \times \text{stddev})$$
Anomalous Variance: Log the precise measurement variance: $$\text{Variance} = \frac{\text{recorded_weight} - \text{expected_weight}}{\text{expected_weight}}$$ [21]
Method Selection Note: You must write a markdown header inside your source code documenting your statistical methodology selection (e.g., standard Z-Score, robust Z-Score, or Median Absolute Deviation [MAD]) and why it maps to the generated physical weight distribution [102, 103].
3.4 Reconciliation Engine Logic & Core Unification
The main engine (reconciliation_engine.py) must seamlessly combine the outputs of Layer 1 (Deterministic) and Layer 2 (Statistical) into a single, unified judgment [105].

Terminology Rule: Do not output subjective labels such as "fraud" or "guilty customer" [101, 105]. Keep outputs strictly technical and objective [101].

4.3 Success Metrics, Formulas, & Targets
You must calculate and log the following metrics for the three baselines and TriNetra [107]:

False Negative Rate (FNR): The proportion of real conflicts that were missed. $$\text{FNR} = \frac{\text{FN}}{\text{FN} + \text{TP}}$$ [28]
TriNetra Target: $\text{FNR} < 0.25$ (must catch at least 75% of actual conflicts) [28].
False Negative Reduction (FNR_Reduction): THE PRIMARY METRIC. The percentage improvement in catching conflicts compared to the best baseline [107]. $$\text{FN_Reduction} = \frac{\text{FNR}{\text{Best Baseline}} - \text{FNR}{\text{TriNetra}}}{\text{FNR}_{\text{Best Baseline}}} \times 100%$$ [26]
TriNetra Target: $\text{FN_Reduction} > 15%$ [27, 33].
Precision: The accuracy of positive conflict flags. $$\text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}}$$ [27]
TriNetra Target: $\ge 0.80$ (to strictly avoid false accusations against honest stakeholders) [27, 33].
Recall: The proportion of actual conflicts caught. $$\text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}}$$ [27]
TriNetra Target: $\ge 0.75$ [27, 33].
F1 Score: The balanced harmonic mean of precision and recall. $$\text{F1} = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$$ [28]
TriNetra Target: $\ge 0.77$ [28, 33].
False Positive Rate (FPR): The proportion of consistent records incorrectly flagged. $$\text{FPR} = \frac{\text{FP}}{\text{FP} + \text{TN}}$$ [28]
TriNetra Target: $\le 0.15$ (prevent operational reviewer alarm fatigue) [28, 33].
4.4 Statistical Significance Rigor (McNemar's / Permutation Tests)
For the primary success metric (FN Reduction), you must run statistical hypothesis tests comparing TriNetra paired binary predictions against the best baseline [32]:

Null Hypothesis ($H_0$): TriNetra False Negative Rate = Best Baseline False Negative Rate [32].
Alternative Hypothesis ($H_1$): TriNetra False Negative Rate < Best Baseline False Negative Rate [32].
Statistical Test: McNemar's Test (for paired binary outcomes) or a Permutation Test (if parametric assumptions fail) [32, 71].
Requirement: Calculate and output the exact $p$-value. Success requires $p < 0.05$ [32, 33].
